# 调味品食品安全问答助手

## 0 阶段

### Windows 启动

安装并启动 Docker Desktop（Linux 容器）。在项目目录运行：

```powershell
Copy-Item .env.example .env
notepad .env
docker compose up --build -d
docker compose logs -f app
```

在 .env 填写自己的 DEEPSEEK_API_KEY，默认模型是 deepseek-flash。也可以先留空密钥启动，测试资料导入。修改密钥后执行 docker compose up -d --force-recreate app。密钥由后端读取，请勿提交 .env。

打开 http://127.0.0.1:8000，进入「知识库管理」，点击「导入首批资料」。首次索引需要从 Hugging Face 下载 BAAI/bge-small-zh-v1.5，所需时间随网络和 CPU 而变。模型缓存与数据库保存在 Docker 卷中。公开资料应显示 238 份文档、4,954 条切片。

首批 CSV 中的 GB 2760 条目只有标为废止的 2014 版。验收当前添加剂限量时，先检查系统能否提示资料不足。数值问答需要补入适用版本的标准及对应食品类别表格。

上传支持 XLSX、DOCX、有文字层的 PDF 和 UTF-8 CSV，每份最多 25 MB。原文件与索引保存在本机，新文件索引完成并手动发布后参与问答检索。已保存的历史引用是当时的快照。通用表格以首个非空行为表头，Excel 公式读取工作簿内的缓存值。

### 验收

1. 导入首批资料两次，核对条目数量并检查重复提示。
2. 上传含可识别文字的 XLSX、DOCX、PDF 各一份，检查状态、切片数量与原文件。
3. 用知识库资料提问，点击引用核对标准号、版本、位置、正文和原始来源。试查标准号、产品分类不明以及资料不足的问题。
4. 检查删除资料后，新问题无法再引用该文件。检查已废止资料在当前查询中的筛选行为，历史查询需结合证据确认废止日期。
5. 重启应用后检查资料和对话是否保留。

使用 docker compose down 停止服务，数据库和模型缓存保留。本部署面向本机单用户，只在回环地址开放应用端口。

## 人员与权限（第一阶段）

- **首次使用**：创建管理员账号；升级前已有会话归属首次创建的管理员。
- **业务人员**：问答、查阅资料、下载原文件，仅能访问自己的会话。
- **维护人员**：具备业务人员权限，另可维护资料和处理导入任务。
- **系统管理员**：另可管理账号、角色和查看操作日志。
- **权限校验**：由后端执行；资料对所有登录人员共享，尚未按部门隔离。
- **登录机制**：有效期 12 小时；使用 HttpOnly、SameSite Cookie，数据库保存令牌摘要。
- **初始化要求**：在可信本机环境完成，新密码至少 10 位。

## 资料维护（第二阶段）

### 功能与规则

- 文件名搜索与固定分类下拉筛选可组合使用。
- 维护人员可编辑分类、说明和发布状态。
- **处理状态**与**发布状态**独立：解析成功不等于已发布。
- 新资料默认草稿，手动发布后才参与新问题检索。
- 停用后不再参与检索，但原文件仍可下载，历史引用保留。
- 升级前已有资料保留为已发布。

### 分类范围

- 法律法规、部门规章。
- 国家标准、行业标准、地方标准、企业标准。
- 文献资料、业务资料、未分类。
- 分类作用于整个文件；首批混合 CSV 内各文档的元数据不受覆盖。

## 资料详情与版本替换（第三阶段）

### 更新流程

1. 在最新版本点击「上传新版本」。
2. 新版继承分类和说明，以草稿状态独立解析；旧版保持原状态。
3. 解析成功并核查内容后，在「编辑与发布」中发布。
4. 系统在同一事务内发布新版、停用所有旧版。

### 限制与保留

- 新版解析失败不影响旧版，可重试或删除失败新版。
- 已有新版发布时，不能直接重新发布旧版。
- 停用新版不会自动恢复旧版。
- 相同内容不重复上传；每个版本只能有一个直接后续版本。
- 有后续版本的文件不能删除，可停用；旧文件和历史引用保留。
- 首批混合 CSV 不支持整体替换，相关标准更新请独立上传。
- 草稿和停用文件仍对登录人员开放查看、下载。

### PDF OCR 补丁

- 无文字层页面自动使用中英文 OCR，保留页码引用。
- Docker 镜像已加入识别依赖，需重建后生效。
- 已用 GB/T 35886—2018 扫描件验证，识别结果可能有错字。

### 运行边界

- 界面、文件解析、中文向量化、索引和会话在本机运行。
- DeepSeek API 会收到当前问题、最近一个用户问题和命中片段。
- 检索排名和回答生成逻辑未在本轮调整。
- 预警接入、文档级元数据编辑仍未实现；操作日志已在第六阶段补齐。

### 验收要点

- 发布 A → 上传新版 B → 确认 A 可用、B 为草稿。
- 发布 B → 确认 A 停用，重新发布 A 应被拒绝。
- 检查版本导航、重复上传提示和业务人员无替换权限。

## 页面分工与导入任务（第四阶段）

| 页面 | 使用者 | 主要功能 |
|---|---|---|
| 资料中心 | 所有登录人员 | 筛选、下载、查看详情和版本 |
| 知识库维护 | 维护人员、管理员 | 上传、编辑、发布、替换、重试、删除 |
| 导入任务 | 维护人员、管理员 | 状态统计、筛选、失败原因、重试 |
| 用户管理 | 管理员 | 创建、启停账号，调整角色和密码 |

- 导入状态每两秒更新。
- 任务记录基于文件当前状态，不保留每次重试的独立流水。
- 使用 Hash 路由，支持直接访问、刷新和前进后退。
- 会话 ID 不在路由中，刷新不会自动恢复此前打开的会话。
- 未授权页面跳转工作台，具体规则见第八阶段。

**验收**：检查角色菜单与操作区别、未授权跳转、刷新与前进后退、失败任务重试。

## 密码与角色管理（第五阶段）

### 本人修改密码

- 入口：右上角账户菜单 →「修改密码」。
- 需验证当前密码，新密码至少 10 位并重复确认。
- 保存后撤销全部登录会话，需重新登录。

### 管理员操作

- 入口：用户管理 →「角色与密码」。
- 可调整其他账号角色或重置密码；密码留空则保留原密码。
- 保存后目标账号登录失效，重新登录使用新角色。
- 不能通过此入口修改本人，避免误失管理权限。
- 重置密码不自动启用已停用账号。

**验收**：检查新旧密码登录、角色变化后的菜单、普通人员无账号管理权限。

## 操作日志（第六阶段）

### 查看与记录

- 入口：管理员「操作日志」，地址 `/#/audit`。
- 记录资料上传、编辑发布、替换、删除、重试。
- 记录账号创建、调整、启停及本人密码修改。
- 显示操作人、时间、对象和 HTTP 结果。
- 支持成功／失败筛选、手动刷新，每页 30 条。
- 编辑或删除前保存对象名称；新建成功后记录名称与 ID。

### 日志边界

- 不记录密码、文件正文、问答内容。
- 不包含登录失败、未登录访问及身份校验前拦截的操作。
- 独立写入日志；写入异常不回滚已完成的业务操作，不属于严格事务审计。
- 数据保存在数据库卷，从升级后开始积累，不补录历史。
- 旧日志中的「新建」缺少关联信息，不自动回填。

**验收**：编辑资料查看成功日志；发布未解析文件查看失败日志；确认普通人员不能访问日志接口。

## 使用帮助（第七阶段）

- 入口：侧栏「使用帮助」，地址 `/#/help`。
- **所有人员**：问答引用、资料筛选、密码管理、处理与发布状态说明。
- **维护人员**：另有上传发布、版本更新和导入排障。
- **管理员**：另有人员管理与日志说明。
- 常见问题可展开阅读，包含扫描件 OCR 核查提醒。

**验收**：分别检查三类角色内容、直接访问与刷新、窄屏展示。

## 工作台首页（第八阶段）

### 按角色展示

- **业务人员**：突出开始问答与资料查阅。
- **维护人员**：突出知识库维护与导入任务。
- **管理员**：突出用户管理与操作日志。
- **公共内容**：最近个人对话、已发布资料、帮助入口。
- 资料按收录时间排序；点击进入资料中心并打开详情。
- 尚无独立发布时间字段，不按发布时间排序。
- 入口卡片统一白底，悬停时高亮。

### 登录与路由

- 无页面地址 → 工作台 `/#/home`。
- 未登录访问具体页面 → 登录后返回该页。
- 无权限或未知页面 → 工作台。
- 已登录刷新 → 保留当前页面。
- 主动退出 → 重置到工作台，下次登录进入首页。

**验收**：检查三类角色首页、退出后再登录、具体链接登录返回、越权页面回退。

## 侧栏与会话查找（第九阶段）

### 界面操作

- 紧凑业务导航，维护和管理入口可折叠。
- 侧栏仅显示最近 10 条个人会话。
- 「⋯」菜单支持重命名、删除。
- 「搜索 / 全部」弹窗支持标题搜索、时间分组和分页，每页 20 条。
- 弹窗支持点击「关闭 ×」或按 Esc 关闭。

### 数据规则

- 搜索与分页由后端执行，仅查询本人会话。
- 按最近回答时间排序；旧会话初始使用创建时间。
- 完整回答保存后更新时间；重命名不改变排序。
- 仅搜索标题，不搜索消息正文。
- `GET /api/chats`：支持 `q`、`page`、`size`，默认返回最近 10 条。
- `PATCH /api/chats/{id}`：修改标题并校验会话归属。

**验收**：创建超过 10 条会话，检查搜索、翻页和重命名；切换账号检查会话隔离。
