# 调味品食品安全问答助手

## 0 阶段

### Windows 启动

安装并启动 Docker Desktop（Linux 容器）。在项目目录运行：

```powershell
Copy-Item .env.example .env
notepad .env
docker compose up --build -d
docker compose logs -f app
```

在 .env 填写自己的 DEEPSEEK_API_KEY，默认模型是 deepseek-flash。也可以先留空密钥启动，测试资料导入。修改密钥后执行 docker compose up -d --force-recreate app。密钥由后端读取，请勿提交 .env。

打开 http://127.0.0.1:8000，进入「知识库管理」，点击「导入首批资料」。首次索引需要从 Hugging Face 下载 BAAI/bge-small-zh-v1.5，所需时间随网络和 CPU 而变。模型缓存与数据库保存在 Docker 卷中。公开资料应显示 238 份文档、4,954 条切片。

首批 CSV 中的 GB 2760 条目只有标为废止的 2014 版。验收当前添加剂限量时，先检查系统能否提示资料不足。数值问答需要补入适用版本的标准及对应食品类别表格。

上传支持 XLSX、DOCX、有文字层的 PDF 和 UTF-8 CSV，每份最多 25 MB。原文件与索引保存在本机，新文件索引完成并手动发布后参与问答检索。已保存的历史引用是当时的快照。通用表格以首个非空行为表头，Excel 公式读取工作簿内的缓存值。

### 验收

1. 导入首批资料两次，核对条目数量并检查重复提示。
2. 上传含可识别文字的 XLSX、DOCX、PDF 各一份，检查状态、切片数量与原文件。
3. 用知识库资料提问，点击引用核对标准号、版本、位置、正文和原始来源。试查标准号、产品分类不明以及资料不足的问题。
4. 检查删除资料后，新问题无法再引用该文件。检查已废止资料在当前查询中的筛选行为，历史查询需结合证据确认废止日期。
5. 重启应用后检查资料和对话是否保留。

使用 docker compose down 停止服务，数据库和模型缓存保留。本部署面向本机单用户，只在回环地址开放应用端口。

## 人员与权限（第一阶段）

首次打开页面时创建管理员账号，密码至少 10 位。升级前已有会话自动归属首次创建的管理员。管理员在「用户管理」创建账号并选择业务人员、知识库维护人员或系统管理员；停用账号会撤销其登录会话。

所有人员只能访问自己的会话。业务人员可问答、浏览资料和下载原文件；维护人员和管理员另可上传、导入、重试、删除资料。权限由后端校验。当前资料对所有已登录人员共享，尚未按部门隔离。

登录有效期为 12 小时。使用 HttpOnly、SameSite Cookie 保存登录凭证，数据库保存令牌摘要。首次初始化应在可信的本机环境完成。

## 资料维护（第二阶段）

资料中心支持文件名搜索和固定分类下拉筛选，两项条件可组合使用。维护人员通过「编辑与发布」维护分类、资料说明和发布状态。处理状态与业务发布状态分别显示。

- 新上传和新导入的资料默认草稿；解析成功后，维护人员手动发布才会参与新问题的资料检索。
- 停用后不再参与新问题检索；已有历史引用保留，已登录人员仍可下载原文件。
- 升级时已有资料保留为已发布，不会因升级自动停用。
- 分类包括法律法规、部门规章、国家/行业/地方/企业标准、文献资料和业务资料。首批 CSV 是混合资料包，分类作用于文件，不会覆盖其内部各文档的元数据。
- 本轮没有修改检索排名或回答生成逻辑，仅增加发布状态准入。

更新运行：`docker compose up --build -d`，启动时自动补充数据库字段。

## 资料详情与版本替换（第三阶段）

点击「详情与版本」查看说明、处理状态、创建时间和前后版本关联。维护人员可在最新版本的「上传新版本」中选择文件：

1. 新版本继承分类和说明，以草稿状态独立解析；原版本保持原状态。
2. 新版解析失败不影响旧版，可重试或删除失败新版。
3. 新版解析成功后，在「编辑与发布」中发布。系统在同一事务内停用所有旧版并发布新版。
4. 已有新版发布时，不允许直接重新发布旧版。停用新版不会自动恢复旧版。
5. 相同内容不能重复上传；同一版本只能有一个直接后续版本。有后续版本的文件不能删除，可停用。旧文件和历史引用保留。

首批混合 CSV 资料包不支持整体版本替换；相关标准更新请作为独立文件上传维护。资料仍对所有登录人员共享，包括草稿和停用文件的查看与下载。

建议验收：上传 A 并发布 → 在 A 上上传不同内容 B → 确认 A 仍可用、B 为草稿 → 发布 B → 确认 A 停用 → 尝试发布 A 应被拒绝；检查前后版本导航、重复上传提示和普通人员无替换权限。

预警接入、操作日志和文档级元数据编辑尚未实现。

浏览器界面、文件解析、中文向量化、检索索引和会话均在本机运行。问答时，DeepSeek API 会收到当前问题、最近一个用户问题及命中的相关资料片段。

补丁：PDF 无文字层的页面自动使用中英文 OCR，保留页码引用；Docker 镜像已加入识别依赖，需重建后生效。已用 GB/T 35886—2018 扫描件验证，识别结果可能有错字。

## 页面分工与导入任务（第四阶段）

- **资料中心**：所有登录人员浏览、按文件名与分类筛选、下载原文件、查看详情和版本，不显示维护按钮。
- **知识库维护**：维护人员和管理员上传资料、编辑发布、替换版本、重试和删除。
- **导入任务**：维护人员和管理员查看处理状态数量、按状态筛选、查看失败原因并重试；每两秒更新。任务记录基于文件处理状态，非每次重试的独立历史流水。
- **用户管理**：仅管理员可见。

采用 Hash 路由：`/#/chat`、`/#/library`、`/#/maintenance`、`/#/tasks`、`/#/users`。支持刷新保留页面、直接访问和浏览器前进后退，不需要额外配置服务器路径回退。未授权页面自动跳转资料中心，接口继续执行后端权限校验。当前对话的具体会话 ID 不在路由中，刷新后不会自动打开此前会话。

更新后执行 `docker compose up --build -d`。验收建议：分别以业务人员和维护人员登录，检查菜单和页面操作区别；直接访问维护路由检查权限回退；刷新与前进后退检查路由；在导入任务中筛选状态并对失败文件重试。


## 密码与角色管理（第五阶段）

所有人员可从右上角账户菜单「修改密码」验证当前密码后修改，新密码至少10位且需重复确认。保存后撤销该账号全部登录会话，需重新登录。

管理员可在用户管理的「角色与密码」中调整其他账号的角色，或设置新密码；密码留空表示不重置。保存后该账号原有登录失效，重新登录后使用新角色。禁止管理员通过此入口调整本人，避免误操作丢失管理权限。停用账号不能登录，重置密码不自动启用账号。接口返回登录失效时，前端返回登录入口。

验收：修改本人密码后旧密码登录失败、新密码成功；管理员调整测试账号角色后该账号重新登录看到新菜单；管理员重置测试账号密码后旧密码失效；普通人员不能访问账号管理接口。


## 操作日志（第六阶段）

管理员可从「操作日志」（`/#/audit`）查看资料上传、编辑发布、替换、删除、重试，以及账号创建、调整、启停和本人密码修改记录。显示操作人、时间、操作对象和 HTTP 结果，支持结果筛选、手动刷新及每页30条分页。对象名称在操作前保存快照，删除文件后仍可辨认。

不记录密码、文件正文或问答内容。当前不包含登录失败、未登录访问以及在身份校验前被拦截的操作。日志独立写入，写入异常时记录服务错误但不回滚已完成业务操作；这是一份业务操作记录，不是严格事务审计。日志保存在数据库卷，升级后开始积累，不补录历史。

验收：维护人员编辑或发布一份资料，管理员确认新日志；尝试发布未解析文件，确认失败日志；普通人员不能打开日志页面或调用 `/api/audit`。重建容器后自动建表，OCR 配置不变。

日志修正：新上传资料和新建账号成功后记录实际名称及 ID，上传校验失败记录文件名。此前显示“新建”的旧日志没有对象关联信息，不自动回填。


## 使用帮助（第七阶段）

新增「使用帮助」（`/#/help`），所有登录人员可访问。内容包含问答与引用、资料筛选、账号密码、处理状态与发布状态的区别；维护人员另可查看上传发布、版本更新和导入排障；管理员可查看人员管理与日志说明。页面按当前角色显示相关内容，常见问题可展开阅读。说明覆盖扫描件 OCR 的核查注意事项，未改变 OCR 实现或镜像配置。

验收：分别登录业务、维护和管理员账号检查帮助内容；通过 `/#/help` 直接访问并刷新；窄屏检查卡片和折叠问答展示。更新命令仍为 `docker compose up --build -d`。


## 工作台首页（第八阶段）

新增 `/#/home`：业务人员突出开始问答与资料查阅；维护人员突出资料更新与导入任务；管理员突出用户管理和操作日志。所有角色可查看最近个人对话、最近收录的已发布资料及帮助入口。当前没有独立发布时间字段，资料按收录时间排序，不按发布时间排序；点击资料进入资料中心并打开对应详情。

无页面地址时默认进入工作台；未登录时访问具体页面链接，登录后返回该页；无权限或未知页面回到工作台。已登录刷新保留当前页面；主动退出登录会重置到工作台，下一次登录默认进入首页。此规则替代之前的无权限跳转资料中心规则。

验收：三个角色分别登录检查首页主入口；从资料页退出再登录检查进入工作台；未登录直接访问 `/#/help` 后登录应返回帮助；业务人员直接访问维护地址应进入工作台。前端构建与类型检查通过，页面实际联调需部署后验收。


## 侧栏与会话查找（第九阶段）

业务导航改为紧凑布局，维护与管理入口归入可折叠的「管理」。侧栏显示最近10条个人会话，按最近回答时间排序；可从「⋯」重命名或删除。通过「搜索 / 全部」弹窗按标题搜索全部个人会话，按今天、昨天、更早分组，每页20条；搜索和分页由后端执行。历史会话更新时间初始取创建时间，后续完整回答保存时更新。

`GET /api/chats` 新增 `q`、`page`、`size` 参数，默认只返回最近10条；`PATCH /api/chats/{id}` 支持重命名，继续按本人归属校验。当前搜索仅匹配标题，不搜索消息正文。

验收：折叠管理分组检查历史区域；创建超过10条会话后在弹窗翻页查找；搜索标题、重命名后再次搜索；使用不同账号检查不能查到他人会话。重建容器自动补充更新时间字段。
