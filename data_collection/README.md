# 独立资料采集工具

从公开网站下载公告和附件，整理成便于查阅的文件。所有内容都在 data_collection 内，**不连接问答系统、数据库或知识库**。

## 当前工作结论

**重庆单来源的基本流程已跑通：采集 → 附件更新检查 → Excel 整理 → 结果报告 → 人工核对。** 使用一条采集命令即可，无需再手动执行表格提取。

| 最近一次完整验证 | 结果 |
|---|---|
| 公开列表 | 2 页、16 篇公告，全部处理，未触及数量上限 |
| 附件 | 49 个均返回“未修改”，无需重复下载正文 |
| Excel | 33 个文件成功整理，无未识别表头或未拆分文本 |
| 整理结果 | 64,217 条产品记录、288 条检测明细 |
| 待人工核对 | 7 条多样本检测记录，已列入 review_required.csv |
| 验证 | 19 项离线测试通过；一键流程已实际运行成功 |

这些是当前样本数量，不代表每次运行都相同，也不代表全部属于调味品。当前公开列表最早为 2026 年 1 月，**尚未补齐五年历史**。
## 1. 目前能做什么

| 功能 | 当前情况 |
|---|---|
| 来源 | 仅接入重庆市市场监督管理局“检查结果及后处置”栏目 |
| 采集数量 | 默认最多查看 3 页列表、采集 100 篇公告及附件；实际数量以网站公开列表为准 |
| 时间范围 | 每次按北京时间当天倒退五年；闰日取有效日期 |
| 文件整理 | 保存公告标题、日期、正文、网址；附件按公告分文件夹 |
| 表格提取 | 读取 XLSX，整理产品和部分检测项目，保留原表位置 |
| 更新检查 | 询问服务器附件是否变化，未变化时不重复下载文件正文 |
| 失败处理 | 临时网络错误有限重试；支持恢复未完成的详情任务 |

**还没完成五年全量采集，也没有覆盖最初讨论的全部网站。** 当前产品清单包含其他食品和保健食品，尚未筛选为纯调味品数据。法规、标准、处罚及文献来源留待后续扩展；现行适用的早期法规标准不统一受五年限制。

## 2. 怎么运行

先启动 Docker Desktop，再在 PowerShell 进入本目录：

```powershell
cd D:\lizhao\lab_proj\seasoning-qa-system\data_collection
```

### 第一步：准备环境

```powershell
docker compose build
```

只构建运行环境，**不会采集**。首次使用、代码或依赖变化后执行；仅修改采集配置不用重新构建。

### 第二步：一键采集和整理

```powershell
docker compose run --rm collector
```

自动完成公告采集、附件下载或更新检查、Excel 整理，最后生成 output/REPORT.md 和 review_required.csv。先看报告，再按待核对清单回原表检查。--rm 只清除临时容器，不删除结果；不会自动定时运行，不需要启动问答系统。

### 可选：只整理已下载的文件

```powershell
docker compose run --rm collector --local-only
```

只读取本地 XLSX，不访问网站。重新生成明细和工作人员报告，不重新采集。若只需要原始提取功能，仍可用 --entrypoint python 执行 extract_excel.py。

### 中断后接着跑

```powershell
docker compose run --rm collector --config config/sources.json --output output --resume
```

按 tasks.json 重试未完成或失败的详情任务，跳过已完成任务。不查找新公告。需要恢复时先用这条命令；普通采集会重建任务清单。列表查找阶段中断，仍需普通采集重跑。

### 强制重新下载附件

```powershell
docker compose run --rm collector --config config/sources.json --output output --force-attachments
```

不用服务器的“未修改”判断，直接下载，用于核查网站更新。文件内容不同会另存，旧原件不覆盖。--resume 仍跳过已完成任务，即使同时使用强制选项。

## 3. 结果在哪里

工作人员优先看下面这些文件：

| output 下的路径 | 用来做什么 |
|---|---|
| REPORT.md | 优先看这里：本轮结果、采集范围、接下来要检查什么 |
| review_required.csv | 产品明细中需要核对的记录，附原文和位置 |
| run_summary.txt | 看最近一轮采集是否成功 |
| run_summary.json | 看失败原因、采集数量和任务进度 |
| records.csv | 看公告清单、正文和原始网址 |
| attachments.csv | 找附件、下载状态、本地路径和原始网址 |
| attachments/ | 打开原始附件，文件名可读 |
| extracted/inspection_rows.csv | 产品清单，一行对应原表的一条产品记录 |
| extracted/inspection_items.csv | 检测项目明细，一个产品可对应多个项目 |
| extracted/extraction_summary.json | 看 Excel 整理是否有遗漏或待核对内容 |
| extracted/sheet_coverage.csv | 看每张表输出、跳过了多少行 |
| extracted/skipped_rows.csv | 看哪些行未输出、原因及原文 |

下面这些主要供程序和排错使用，不必逐个打开：

| 路径 | 用途 |
|---|---|
| records/ | 每篇公告的 JSON 档案，用来更新及重新生成清单 |
| raw/ | 原始网页，哈希文件名用于核对；不放旧版附件 |
| quarantine/ | 日期或正文异常的公告档案，需核查，不进入公告 CSV |
| excluded/ | 超出日期范围的公告档案，不进入公告 CSV |
| tasks.json | 本轮选中的详情任务及完成进度 |
| runs.jsonl | 累计执行日志，排查具体请求 |
| pagination_check/ | 曾用于分页测试的临时副本；正式采集不依赖它 |

同一公告只保留一个当前 JSON 状态，原件仍保留。网络失败时可能保留旧档案，不能把它误认为本轮更新成功。附件清单包含各类档案中的附件，用 record_state 区分。

采集汇总每轮覆盖，日志持续追加。CSV 和表格整理结果会重新生成。不要同时启动多个程序写同一个 output。CSV 含网页原文，勿执行原文带入的表格公式。

## 4. 怎么判断运行是否正常

### 采集结果

打开 run_summary.json：

| 字段或状态 | 含义 |
|---|---|
| success | 本轮没有记录到失败或隔离，仍需业务审核 |
| needs_review | 有日期或正文异常的公告 |
| partial_failure | 页面或附件有失败，查看 errors |
| attachment_saved | 本轮完整下载并保存的附件数量 |
| attachment_not_modified | 服务器返回 304：附件未变，保留本地文件 |
| detail_limit_reached: true | 找到的公告多于下载上限，还没全部采集 |
| task_counts | 任务完成、失败及待执行数量 |

例如 attachment_not_modified 为 16，表示 16 个附件不需要重复下载正文。已经在重庆本批附件上实际验证成功；其他网站或未来响应可能不同。

ETag 和 Last-Modified 是服务器提供的文件版本标记，保存在附件清单。无标记、文件丢失或本地校验失败时，会完整下载。基础校验能拦截空文件、错误网页及部分类型不符文件，但不能保证文档内容正确。

网络超时和部分临时错误最多尝试 3 次。403、404 不反复重试；服务器要求等待超过 60 秒时停止，稍后再运行。详细日志查看：

```powershell
Get-Content .\output\runs.jsonl -Tail 20
```

### Excel 整理结果

**“无异常”不等于“所有数据都正确、完整”。** 网站改变表头、合并单元格或排版，都可能让原规则失效。

| 检查项 | 去哪里看 |
|---|---|
| 文件打不开、表头认不出 | extraction_summary.json 的 issues |
| 有多少复杂检测文本未拆开 | unparsed_result_rows |
| 有多少多样本检测记录要人工核对 | sampling_plan_rows；明细的 parse_status |
| 哪些行被跳过 | skipped_rows.csv |
| 输出行数是否能对上原表 | sheet_coverage.csv |
| 某条结果来自哪里 | 明细中的附件网址、sheet、row、result_cell |

行数分为：空行、表头、表头前内容、产品输出、表头后跳过行；五类合计等于文件实际存储的行数。标题说明属于表头前内容，不一定是错误。

status 为 needs_review 时需排查；completed_pending_review 表示通过现有检查，仍待人工审核。文件异常和表头后跳过行会使命令返回 1；仅有复杂检测文本未拆分时不一定返回 1，因此也要看状态和数量。

每次抽查几条原表和结果，尤其检查新格式、检测值、单位、标准值及来源位置。当前仅识别部分表头；数值和日期保留底层原值，未套用 Excel 显示格式，公式只读缓存并标记。

## 5. 检测明细有什么用

原表可能把多个结果放在同一格：

> 铅║0.2mg/kg║≤0.1mg/kg；菌落总数║100CFU/g║不得检出

程序将能明确识别的内容整理为：

| 检测项目 | 检测结果 | 原表中的标准值 |
|---|---|---|
| 铅 | 0.2mg/kg | ≤0.1mg/kg |
| 菌落总数 | 100CFU/g | 不得检出 |

上例仅演示格式，不是实际产品判断。拆不清的保留原文，在产品清单中标记“待核对”。不凭空补充合格表里没有的检测结果，不换算单位，不判断超标或处罚。

每条明细保留“原始网址 → 附件 → 工作表 → 行号/单元格”，为以后展示回答依据做准备；当前没有导入问答系统。

### 新增业务列怎么读

| 列名 | 含义 |
|---|---|
| manufacturer、manufacturer_address | 原表标称的生产企业及地址 |
| sampled_unit、sampled_address | 被抽样单位及地址 |
| sampled_province、sampled_district | 原表中的省份、区县 |
| specification、brand | 规格、商标 |
| production_date、batch_no | 原表单独列出的生产日期、批号 |
| production_date_or_batch | 原表合写的“生产日期/批号”，不强行拆开 |
| test_agency、tested_items_raw | 检验机构、原表检验项目 |
| food_category、remarks | 食品类别、备注；没有就留空 |
| field_cells | 各字段在原表中的单元格位置 |

旧 batch 列为兼容保留，可能是日期或混合文本，不能直接当成批号。本批原表没有食品类别列，food_category 留空。

“一个项目测多个样本”不等于“多个检测项目”。遇到含 n、c、m、M 的多样本方案，完整保留结果并提示人工核对，不自动判定合格。Excel 上标等显示样式尚未保留，例如“×105”需回原表确认，不能直接拿来计算。
## 6. 常用配置

修改 config/sources.json：

| 配置 | 含义 |
|---|---|
| enabled | 是否采集该来源 |
| url、id | 来源入口及标识 |
| max_details | 最多采几篇公告，当前 100 |
| max_list_pages | 最多查几页列表，当前 3 |
| lookback_years | 设为 5 表示滚动五年；省略则不限制历史年份 |
| download_attachments | 是否下载附件 |
| pagination | 重庆用 wcm，读取网页提供的页码参数 |
| resource_type、region、publisher | 资料类型、地域及发布单位 |

维护人员才需调整：page_type（入口是列表还是详情）、list_link_selector（详情链接位置）、next_page_selector（普通下一页链接位置）、body_selector（正文位置）、date_selector（日期位置）、detail_urls（补充详情网址）、min_content_chars（正文最少字符数，默认 150）。重庆页面的标题和日期优先取官方元数据。

详情和附件仅访问同域；单份下载上限 25 MB，Office 解压总量上限 150 MB。请求至少间隔两秒，遵循 robots.txt。访问受限或重定向时需核实来源，不绕过限制。

### 日常运行需注意

- 正常采集会重建任务清单；有中断任务时，先用 --resume。
- 恢复模式也会自动整理并生成报告，但不查找新增公告。
- --local-only 只整理本地文件，不更新采集汇总，不能据此判断网站采集成功。
- 采集失败时，历史档案仍可能进入整理结果；看 REPORT.md 时要区分“本次采集”与“全部已保存资料”。
- review_required.csv 只列产品记录的待核对项；文件打不开、未知表头和跳过行还要看提取汇总及 skipped_rows.csv。
- 命令正常退出不等于业务审核通过；7 条多样本记录仍需人工确认。
